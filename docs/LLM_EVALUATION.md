# LLM evaluation

**Question:** is the generated report faithful to the analytics facts? Instead of judging by eye, we score every report against its input payload.

| Metric | Definition | Goal |
|---|---|---|
| Reports really from the LLM | How many of the evaluated months were generated by the LLM (the script counts failures instead of silently using the fallback) | all |
| Valid schema | Output parsed as JSON and matched the 5-field report schema | 100% |
| Unsupported-number rate | Metric numbers in the text that do not appear in the payload / all metric numbers | 0% |
| Driver coverage | Share of top growth drivers (Region, Category, Product) named in the report | high |
| Decline coverage | Share of top decliners named in the report | high |
| Causal phrases | "because", "due to", "caused by"... (the prompt forbids unsupported causes) | 0 |
| Recommendation leakage | "should/must/recommend" inside the fact sections | 0 |

## Run it
```bash
python scripts/evaluate_llm.py --max-months 12
```
Without an API key it scores the rule-based fallback (the baseline). With a key in `.env` it scores the real LLM on the same monthly payloads; if the AI service fails for a month (503, rate limit) that month is counted as **failed**, never replaced by fallback text, and the script prints a warning. Check the line "Reports really generated by the LLM: n of n" before you quote any result. Output: `reports/llm_evaluation.md` and `.csv`.

## How to use the result in your report
1. Run once without a key (baseline) and once with a key (LLM). Put both result tables side by side.
2. Discuss any non-zero unsupported-number rate: which numbers, why (unit conversion? rounding?), and how the prompt or validation can fix it.
3. Mention that the same checks run in production: the app shows a warning when an AI number is not found in the data.

## Honest limitations
Number matching cannot detect a *wrong sentence built from correct numbers* (for example attaching a number to the wrong region). Coverage and the causal-phrase count are proxies; a human review of a sample is still recommended.
